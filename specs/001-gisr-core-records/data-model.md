# Data Model: GISR Core Records

PostgreSQL 16+ with `vector`. All primary keys are `uuid` generated by the application. `*_at` columns
are `timestamptz` (UTC); `*_on` and engagement dates are `date`. Names are snake_case. Database row
models stay inside `Gisr.Database`; the API exposes DTOs only.

## Entities

### account
Login identity and settings. Created automatically on first sign-in; independent of records.

| Column | Type | Notes |
|--------|------|-------|
| id | uuid PK | |
| tenant_id | uuid NOT NULL | Entra `tid` |
| entra_object_id | uuid NOT NULL | Entra `oid`; UNIQUE with tenant_id |
| display_name | text NOT NULL | 1-100 chars; initial value from token, editable |
| sign_in_email | text NULL | from token; read-only |
| contact_email | text NULL | editable; valid email, max 254 |
| notify_on_service_record | boolean NOT NULL DEFAULT true | |
| created_at | timestamptz NOT NULL | |
| last_sign_in_at | timestamptz NULL | null for a placeholder created by an Officer for a tenant member who has not signed in yet |

The Officer credential is **not stored**; it comes from the `roles` claim.

### record
A citizen record (self-authored or a service record).

| Column | Type | Notes |
|--------|------|-------|
| id | uuid PK | |
| subject_account_id | uuid NOT NULL FK account | the citizen the record is about |
| author_account_id | uuid NOT NULL FK account | creator; from token claims |
| title | text NOT NULL | 1-200 chars |
| affiliation | text NOT NULL | one of catalog codes (validated in API) |
| engagement_start | date NULL | |
| engagement_end | date NULL | must be >= start when both present |
| engagement_detail | jsonb NOT NULL DEFAULT '{}' | affiliation-specific values; unknown keys preserved |
| is_sealed | boolean NOT NULL DEFAULT false | only service records may be sealed |
| override_code_hash | text NULL | `pbkdf2-sha256$iterations$salt$hash`; never returned or logged; required exactly when `is_sealed` |
| version | integer NOT NULL DEFAULT 1 | optimistic concurrency |
| created_at, updated_at | timestamptz NOT NULL | |
| updated_by_account_id | uuid NOT NULL FK account | |

- **Service record** = `author_account_id <> subject_account_id` (derived; exposed as `isServiceRecord`).
- Indexes: `(subject_account_id, updated_at DESC)`, `(affiliation)`.
- A user may own any number of records; none are created automatically.
- Records are never deleted in this feature.
- Constraints: `CHECK (NOT is_sealed OR author_account_id <> subject_account_id)` and `CHECK (is_sealed = (override_code_hash IS NOT NULL))`.
- **Locked for a caller** (used by every query that returns record content): `is_sealed AND caller is not Officer AND the request carries no valid, unexpired, unrevoked view grant for (record, caller)`. Locked records appear in lists only as redacted sealed entries (subject only) and are excluded from artifact, history, and search results.
- **Gallery rule**: gallery queries exclude every record with `is_sealed = true` for all callers, including Officers. Sealed artifacts are reachable only from the record page.

### record_view_grant
A single-viewing, view-only grant created by a correct override code. The raw token goes only to the Web server (never the browser).

| Column | Type | Notes |
|--------|------|-------|
| id | uuid PK | |
| record_id | uuid NOT NULL FK record | |
| account_id | uuid NOT NULL FK account | the subject who entered the code |
| token_hash | bytea NOT NULL UNIQUE | SHA-256 of a 32-byte random token |
| created_at | timestamptz NOT NULL | |
| expires_at | timestamptz NOT NULL | created_at + 15 minutes (backstop) |
| revoked_at | timestamptz NULL | set when the viewer leaves the page |

Multiple grants may exist (one per open viewing). All rows for a record are deleted when its `is_sealed` or override code changes. Expired and revoked rows are purged periodically.

### record_override_attempt
Audit and throttling (FR-042).

| Column | Type | Notes |
|--------|------|-------|
| id | uuid PK | |
| record_id | uuid NOT NULL FK record | |
| account_id | uuid NOT NULL FK account | |
| attempted_at | timestamptz NOT NULL | |
| succeeded | boolean NOT NULL | the code entered is never stored |

Index `(record_id, account_id, attempted_at DESC)`. Lockout: 5 failures within 15 minutes for the same `(record, account)` block further attempts until the oldest of those failures is 15 minutes old.

### ocr_usage
Cost guard for the scanned-PDF fallback (research D-21).

| Column | Type | Notes |
|--------|------|-------|
| month | date PK | first day of the UTC month |
| pages_used | integer NOT NULL | pages reserved for OCR this month |

Pages are reserved atomically before each OCR call (`UPDATE ... SET pages_used = pages_used + @pages WHERE month = @month AND pages_used + @pages <= @budget`, inserting the month row first); a failed reservation means the budget is exhausted. Unused reservations are not refunded when a call fails.

## Affiliation catalog (code-defined in `Gisr.Api/Affiliations`)

Every affiliation includes the common required field `summary` (multiline, max 4000). Field values are
stored in `record.engagement_detail` under the listed key.

| Code | Name | Additional fields (key: type, required?) |
|------|------|------------------------------------------|
| `civilian` | Civilian | `homeworld`: text; `occupation`: text; `employer`: text (optional) |
| `military` | Military | `branch`: select (Navy, Army, Starfighter Corps, Marines, Other) req; `rank`: text req; `unit`: text; `service_number`: text |
| `jedi` | Jedi | `order_rank`: select (Youngling, Padawan, Knight, Master) req; `mentor`: text (optional); `specialization`: text; `temple`: text |
| `bounty_hunter` | Bounty Hunter | `guild_registration`: text req; `license_status`: select (Active, Suspended, Expired) req; `contract_client`: text; `primary_target_category`: text |

Unknown keys are preserved on affiliation change but not shown unless the record returns to that affiliation.

## State transitions

- **Record**: `created (v1)` -> `updated (v+1)` on each successful save; a stale `expectedVersion` yields 409 and no change.
- **Artifact.index_status**: `pending` -> `indexed` | `failed` | `skipped` (unsupported type, no extractable text, or OCR unavailable; see `index_detail`). `failed` can return to `pending` through manual re-queue/retry. Artifacts skipped with `ocr_budget_exhausted` are re-queued automatically at the start of the next month. Removal sets `removed_at` and deletes its chunks.
- **search_index_job.status**: `pending` -> `running` -> `succeeded` | back to `pending` (attempts < 5, backoff) | `failed` (attempts = 5). When the embedding service itself is unavailable (network error, timeout, 401/403/408/429/5xx, no Azure credential) the job is deferred for a minute and the attempt is handed back, so an outage never fails a job; only other errors count toward the 5 attempts.
- **Sealed record**: `locked` -> `viewing (grant active)` on a correct code -> `locked` when the viewer leaves the page (grant revoked), after 15 minutes (grant expires), or on any change to `is_sealed`/override code or unseal. A correct code never changes the record itself, and each new visit starts again from `locked`.
- **Notification**: unread (`read_at` null) -> read.

## Access rules (summary; see research D-6)

| Operation | Subject, not Officer | Officer | Other user |
|-----------|---------------------|---------|-----------|
| View record, artifacts | yes, unless locked (403 `sealed`; the override form is always offered); during an override viewing the record and its artifacts are readable with the view token; history and artifacts of a locked record: 404 | yes (access logged if not subject) | 404 |
| Create record | self only (never sealed) | any tenant member (placeholder account created on demand); may seal | self only |
| Edit record / manage artifacts | only if also the author, and not while locked | yes (including seal and override code) | no |
| Enter override code | yes, on own locked sealed records | n/a | 404 |
| List / gallery / search `scope=all` | 403 | yes | 403 |
| Own record list (`scope=mine`) | locked records shown as redacted sealed entries; excluded from search | all | n/a |
| Gallery | sealed records never appear, for any caller | same | n/a |

## Validation rules (FluentValidation)

- Title, affiliation required; affiliation must exist in the catalog.
- `engagement_detail` validated against the affiliation's field definitions (required, type, select options, max lengths); `summary` required.
- Dates are valid calendar dates; `engagement_end >= engagement_start`.
- Collection and size limits as above; incident/award titles/names required.
- Update requests require `expectedVersion`.
- `isSealed = true` requires the caller to hold Officer, the record to be a service record, and a non-empty `overrideCode` (8-64 chars) in the same request. When already sealed, `overrideCode` is optional (omitted = unchanged; provided = replaced). Unsealing clears the code. Override entry: non-empty, max 64 chars.
- Snapshots in `record_revision` include `is_sealed` and whether a code exists, never the hash.
- Upload: size, allowed type (by sniffed bytes), non-empty, image description required.
- Search: `q` 2-500 characters after trimming; `pageSize` 1-50.
